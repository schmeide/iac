# `postgres` module

The one shared Azure Database for PostgreSQL flexible server. It holds a database per project, created by the platform
at runtime, and the platform's own databases, created here: the customer database, Temporal's two, and Forgejo's.

- **Private access only**: the server sits in the delegated subnet from `modules/network` and resolves through its
  private DNS zone. `public_network_access_enabled` is false, so nothing outside the VNet reaches it.
- **Burstable `B_Standard_B2s`**, PostgreSQL 17, 32 GiB with auto-grow. B1ms is cheaper but allows about 50
  connections, fewer than Temporal opens.
- **Backups on**, 7-day point-in-time restore, locally redundant. Raise `backup_retention_days` (up to 35) before real
  data lands.
- **`azure.extensions` allows `BTREE_GIN`**, which Temporal's visibility schema creates.

Sizing, the connection pooler and per-database limits are not decided.

## The admin password

Generated by an ephemeral `random_password` and sent to the server and to the platform Key Vault (secret
`postgres-admin-password`) through write-only arguments. It is never in state or in a planfile. To rotate it, bump
`administrator_password_version`; the next apply generates a new one and writes both.

Temporal and Forgejo connect with this login for now (see `gitops/README.md`). Per-project logins are the platform's
job.

## Connecting by hand

The server is private, so connect from inside the cluster:

```bash
kubectl run psql --rm -it --image=postgres:17 -- \
  psql "host=psql-schmeide.postgres.database.azure.com user=schmeideadmin dbname=schmeide sslmode=require"
```
